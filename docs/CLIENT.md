# Shared client engineering

React + TypeScript runs in the browser and Tauri 2 shell. `src/ui/` remains untouched after the initial milestone: Opus owns presentation, interactions, themes and motion. `App.tsx` adapts server data and intents to the unstyled `Screen` contract; `hooks/`, `state/`, `transport/`, and `data/` own implementation. No visual styles or third-party trackers are included.

Run `cd client && npm ci && npm run dev`; Vite proxies `/api` to `CHRISCORD_API` (default `http://127.0.0.1:3000`). `npm run build` typechecks and outputs `dist/`. Production serves that directory beside the API. A packaged native client takes a server URL on the authentication form; only HTTPS is accepted except loopback development. `VITE_API_ORIGIN` supplies an optional build-time default, never a secret. The API must explicitly allow the native app origin. Invite links contain the single-use invite token in the fragment, so the HTTP server and referrer do not receive it. Accepted tokens are removed from browser history.

Authentication sessions and device secrets live only in memory; reload requires sign-in. They never enter URLs, persistent browser storage, logs, or presentation props. This reduces persistent credential exposure while secure native storage remains pending. Logout revokes the current server session. Device UI can revoke another session. Browser fetch omits cookies, disallows redirects, and disables cache. The Tauri shell exposes no filesystem, shell execution, or remote IPC plugin permissions.

The currently wired slice includes WebAuthn registration and sign-in, first-run setup, invite redemption, password sign-in, owner invite issuance, chunked upload/pause/resume/quarantine and attachment selection, conversation listing, messages, edits with revision, replies, user mention completion, reactions, pins, search, DMs/group DMs, consented text reports, report resolution, device revocation, and one-second durable event polling. Server events trigger authorized refetches. Unsend installs a permanent in-memory tombstone and closes matching browser notification handles. Tombstones beat late responses and out-of-order edits. No cached message is displayed across a reload. This is actual browser notification closure while the process runs, not a claim of background APNs/FCM delivery or offline operating-system alert erasure.

Native secure credential storage, background push, dedicated thread views, role/everyone mention completion, rich markdown/embed rendering, provider playback (Plex/DJ/VM), theme implementation, screenshot reporting and native invite deep links remain unimplemented. Browser voice transport now includes microphone/camera, optional screen share, incoming tracks, target stereo/fullband 510 kbps, optional noise suppression, mute, and counters; actual SFU interoperability and latency remain pending until browser evidence below. Activity panels synchronize server control state and clearly label provider playback unavailable. Gimme exposes dry-run preview only. Giphy results retain attribution and select a link into the composer when a server key is present. The contract inventory is broader than this completed slice. No placeholder is acceptance evidence.

## Tests and evidence

`npm test` covers stale response resurrection after unsend, revision ordering, channel isolation, notification closure and ordering, insecure origin rejection, and precise mention matching. `npm run e2e` launches the compiled `target/debug/chriscord-server` in an isolated temporary database with loopback API port 3031 and frontend port 1420. It sets a fixture bootstrap token and media key, removes its own directory on exit, and never wipes existing user databases. The test opens three isolated browser contexts against the real API and covers setup/invites, realtime messages, mentions, browser notification closure after unsend, edits, replies, pins, search, private DM isolation and session revocation. It also validates WebAuthn using a Chromium virtual authenticator, rejects registration/assertion replay, checks the old bearer after revocation, synchronizes all three activity control types, previews Gimme without provider mutation, and tests fail-closed quarantine after a 5 MiB upload. It uses a deterministic Notification adapter to observe OS notification calls without desktop permissions, not an API mock. JSON results and a screenshot are written under `evidence/client-*`. Playwright tracing and automatic failure screenshots are disabled to avoid recording auth headers or request credentials. The manual success screenshot contains only fixture conversation data.

## Native packaging

`npm run tauri -- build` builds the Linux shell after installing [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/). Android needs Java, Android SDK, NDK and Rust Android targets, then `npm run tauri -- android init` and `npm run tauri -- android build --apk`. iOS project generation/build needs the Mac toolchain: `npm run tauri -- ios init`, then `npm run tauri -- ios build`. Android project generation succeeded locally in `src-tauri/gen/android` (evidence/client-android-init.txt). The generated CLI template requested unavailable Android 37; compile/target SDK are pinned to installed stable API 35 pending actual dependency validation. Android manifest declares microphone/camera permissions; runtime permission behavior still needs emulator/device verification. Native artifacts and device tests count as pending until recorded evidence exists. Source scaffolding alone is not a successful native build.

Maya iOS validation: install a development-signed build; exercise invite → server URL → authentication, secure-origin handling, camera/microphone permission denial/acceptance when voice lands, foreground/background reconnection, revoked sessions, notification retraction when app runs, rotation and screen-reader labels. WebAuthn native associated domains/entitlements and deep-link registration still need implementation before passkey onboarding acceptance.

## Contract changes for root handoff

Append to UI-CONTRACT changelog: login/setup/invite fields include optional `server_origin`; device secret storage is currently memory-only. Generic field types add `file` for functional upload selection. Voice stream binding lives in the engineering MediaTrack adapter, using an unstyled browser media element, with no custom visuals. Generic composer receives mention-candidate items with `mention` intent and `itemId=user.id`; engineering collects draft input and throttles typing transport. Message item actions are reply/react/pin/edit/unsend. Search/pins reuse current channel; all list/query content filters durable deletion tombstones. Native/background capabilities remain unavailable and are not advertised as shipped.
