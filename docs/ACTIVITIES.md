# Activities implementation and integration boundaries

`crates/activities` is a standalone Rust crate. `server/src/activities.rs` persists activity state transactionally in SQLite and emits channel events. This is working synchronized **control state**, not evidence of synchronized media playback. When the SFU is configured, every activity request requires a connected voice session and the roster comes from connected SFU peers. With SFU disabled, the explicitly labeled control-state prototype uses channel membership. Actual provider media playback remains unfinished.

## State protocol

`Session::new(kind, host, members, now_ms)` accepts Plex, DJ or VM and 1–30 authorized members. `apply(actor, expected_revision, Command, now_ms)` authorizes, validates against the current revision, applies atomically, and returns a snapshot. Stale commands return conflict; refresh the snapshot instead of blindly resubmitting. Failed commands do not alter state. Use server time in milliseconds consistently; browsers must not supply it. `snapshot` rejects outsiders. `replace_members` is a trusted server-only revocation hook. Persist the session before broadcasting the returned snapshot.

Every snapshot contains `kind`, `revision`, `server_time_ms`, `host`, `members`, `playback`, `queue`, `skip_votes`, `controller` and `control_requests`. Playback has media ID, duration, playing flag, anchor position and anchor time. Clients estimate the offset to the server clock, derive the current position from the anchor, and correct drift. Audio/video playback drift and glass-to-glass delay have **not** been measured by these domain tests. Reconnecting clients receive the latest full snapshot. `tick(now_ms)` ends finished media, advances DJ queues and expires VM control, returning a snapshot when state changed. The HTTP integration advances on requests; continuous timed broadcasting still needs a worker.

Commands:

- Plex: host selects a numeric Plex item ID and duration, plays, pauses or seeks. Selection and duration must ultimately come from validated Plex metadata.
- DJ: each member enqueues a track; server overwrites requester identity. Only requester or host removes a track. Unique users vote to skip; strict majority skips. Host can skip directly. Queue is capped at 500 metadata entries, not media bytes.
- VM: request control, explicit handoff, renew or release. Control expires in 30 seconds. Every input packet must call `authorize_input`, including packets on existing sockets. Departing members lose control immediately. Snapshot reset and the VM gateway are infrastructure concerns, not implemented by the state machine.

The authenticated server routes are `GET/POST/DELETE /api/channels/{id}/activity`, `POST /api/channels/{id}/activity/commands` and `POST /api/channels/{id}/gimme/requests`. Start body is `{"kind":"plex"}` (or `dj`, `vm`); command body is `{"expected_revision":0,"command":{"type":"select","media_id":"42","duration_ms":10000}}`. Route tests cover anonymous and cross-channel denial, three viewers, stale writes, host restrictions and membership removal.

## Provider adapters

Plex's token stays in an `X-Plex-Token` server header; it is never included in returned DTOs or URLs. `Plex::libraries`, `browse` (100 items/page), `metadata`, `transcode` and `subtitle` construct real PMS requests. Redirects are disabled. All client-supplied IDs are numeric. Transcoding requests HLS/H.264/AAC, including a subtitle selection. `server/src/plex.rs` now supplies an authenticated HLS gateway: every provider route requires the current Plex activity and connected voice membership. It rewrites URI lines and URI-valued attributes (nested playlists, subtitles, maps and encryption keys) to channel-scoped opaque `/api/` resources. The gateway rejects off-origin links, redirects, credentials in URLs, escaped paths and non-transcode resource paths. Query tokens are removed and the server injects its own header. Browser requests never receive a provider URL. Same-selection playback is shared across viewers; only the host can select a burn-in subtitle. It streams each segment through a bounded two-chunk queue rather than buffering a movie, with a 64 MiB segment ceiling and 1 MiB manifest ceiling. Device sessions, connected voice membership and current selection are rechecked during streaming. The registry is limited to 30 rooms, 8,192 resources per session and 32,768 total resources, with 32 simultaneous fetches and 30-minute idle expiry. Activity stop, explicit playback stop, replacement and idle cleanup remove resources and request provider transcode stop (best effort). HLS upstream credentials/redirect/cookie headers are never forwarded. The API choices follow the [official PMS reference](https://developer.plex.tv/pms/), including its JSON Accept header, transcode endpoint and stream metadata.

DJ `Resolver::resolve` accepts strictly validated YouTube/SoundCloud track URLs or text search. Spotify track URLs fetch catalog title/artist with a server-held token and resolve a YouTube search. This is a candidate match, not an acoustic identity guarantee; a confidence/review UI and fallback matching remain outstanding. `yt-dlp` executes without a shell or user config, with process timeout and bounded output. Short-lived CDN URLs are server-private and excluded from serialized responses. Fetch them only from an isolated media worker with controlled outbound networking; the resolver itself is not a complete SSRF sandbox for extractor redirects. See [yt-dlp CLI documentation](https://github.com/yt-dlp/yt-dlp) and [Spotify Get Track](https://developer.spotify.com/documentation/web-api/reference/get-track). Spotify access-token acquisition/refresh is not yet supplied by this adapter.

Switchboard uses the prescribed local endpoint, `model: role:chat`, and `X-Inference-Task: housecall.dj`. Song titles are sent as untrusted metadata. A localhost-only override enables fixtures. Banter generation and local speech are implemented adapters; scheduling banter between actual streamed songs remains outstanding. See [DJ-REFERENCE.md](DJ-REFERENCE.md).

## Gimme v2

Read the user-requested skills at `~/.hermes/skills/media/gimme-movie-requests/SKILL.md` and `~/.hermes/skills/media/gimme-app-operations/SKILL.md`, plus the first skill's `scripts/request.py`. The authoritative v2 section supersedes its legacy examples. No live Gimme service was called or changed.

`Gimme` defaults to dry-run. Discovery requires API version 2 from capabilities and contract, and all requests use `x-api-key`. Each submitted operation has an explicit idempotency key; reusing a key with a different body is rejected in-process. Live adapter calls accept only HTTP 202 submissions and strict relative job paths; HTTP 200 polling alone is not success. Completed jobs preserve `result_status` and `result`. A confirmation-required result remains a proposal: this adapter has no torrent confirmation/cancellation endpoint. Pending jobs preserve the job ID/path for later polling, and Retry-After seconds precede body delay. Redirects are disabled. The caller must persist intents/jobs and implement bounded retry orchestration; no automatic retry loop is included.

The server route is explicitly **dry-run only**: it returns the intended operation and publishes `gimme.dry_run`, with `provider_verified:false`. It does not claim that a movie was requested or downloaded. Its v2 discovery documents are fixtures. Live contract schema validation beyond version discovery, durable job processing/status posts, and deployment with real credentials remain unfinished.

## Configuration and verification

Provider configuration must be read from environment by the server composition root: `PLEX_URL`, `PLEX_TOKEN`, `SPOTIFY_ACCESS_TOKEN`, `SWITCHBOARD_API_KEY`, `YT_DLP_PATH`, `GIMME_URL`, `GIMME_AGENT_API_KEY`, `DJ_TTS_PROVIDER`, `DJ_REFERENCE_WAV`, `DJ_XTTS_MODEL_DIR`. Do not put credentials in client builds or logs.

Run `cargo test --manifest-path crates/activities/Cargo.toml -j 1`. Evidence: `evidence/activities-tests.log`; server tests have separate root-owned evidence. Provider tests are local TCP fixtures, not real Plex/Spotify/Switchboard/Gimme validation. Property tests fuzz song URL normalization, protocol JSON parsing and playback arithmetic. The SFU now has real three-browser fake-device decoded audio/video evidence under `evidence/client-voice-three-user.json`; activity provider playback remains separately verified. Plex URI rewriting/property/range/redirect tests use loopback fixtures; live Plex compatibility and physical clock/display latency still require separate measurement. Local clone performance and the VM guest/WebRTC bridge remain open. The VM namespace policy and IPv6 kernel hook have disposable-container evidence in `evidence/vm-*`, which is not guest proof.

The HLS rewrite rules cover the URI-bearing forms in [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216), including quoted attribute lists and nested rendition playlists. Unsupported or malformed forms fail closed.

## Plex gateway HTTP contract

All paths below are under `/api/channels/{channel}/plex` and use normal bearer plus device-key headers. The client must be connected to voice and the current activity must be Plex. Browser HLS loaders must attach those headers on every playlist/segment request and reject redirects.

- `GET /sections` returns `{libraries:[{id,title,kind}]}`.
- `GET /items?section={id}&start=0` returns `{items:[{id,title,kind,duration_ms,subtitles}]}` with at most 100 items. `GET /metadata/{rating_key}` returns one such item. Subtitle DTOs contain only `{id,language,codec,embedded}`.
- Select a rating key using the ordinary revisioned activity `select` command and metadata duration, then `POST /playback` with `{rating_key,subtitle_id?}`. A viewer may start/reuse the selected item. Only the activity host may specify a burn-in subtitle ID, validated against that item's metadata. Response is `{playback_id,rating_key,manifest_url}`; identical viewer requests share a transcode session.
- `GET /playback` returns that descriptor for reconnect. `DELETE /playback` is host-only. `plex.playback` channel events carry a new descriptor after startup/replacement.
- `GET /resources/{opaque_id}` authorizes the current channel/activity/voice session again. HLS manifests contain only rewritten `/api/channels/...` URLs. Segment requests support a single bounded byte range and never redirect. Every response is private/no-store.

Missing provider configuration or configured voice returns 503 to an otherwise authorized activity member. Authenticated outsiders remain forbidden. No Plex token, fixture credential or Gimme key is stored in the client. The current policy deliberately fails closed on unsupported HLS grammar or provider resource paths; actual Plex-version compatibility is not claimed from fixtures alone.
