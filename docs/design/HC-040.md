# HC-040: the Housecall 0.4.0 design spec

Binding for every UI change in 0.4.0. Written by the design authority (plan D-1). Implementers build exactly this and make no visual decisions. Where this document is silent, use the closest pattern it defines and say so in your receipt.

**How to use it**

- Each section gives anatomy (the DOM to render), sizes and tokens, every state, phone and desktop behaviour, motion, copy, and the CSS to paste.
- The CSS in this document is copied by script from `design/040/css/*.css`, the same files the mockups load. If the two ever differ, the css file wins; run `node design/040/sync-spec.mjs`.
- Mockups: `design/040/<surface>.html`. Open one straight from disk (`file://`), add `?s=<state>` for a state listed in its `<meta name="hc-states">`. Pictures of every mockup, 1280x800 and 390x844, dark and light: `design/040/shots/`. Refresh them with `node design/040/shoot.mjs`.
- Lines marked `mock-only` in the css files exist to cancel a 0.3.0 rule that the new block replaces. They are not in this document. When you paste a block, delete the 0.3.0 rules it names.
- All visible text goes in `client/src/ui/copy.ts`. The strings are given per section under "Copy" with the key to use. Sentence case, no em dashes, no exclamation marks, no trailing ellipsis character.
- Class names keep the `hc-` prefix. Existing test ids and internal ids do not change.
- Breakpoints are the existing ones: phone at `max-width: 47.5em`, right column as a sheet at `max-width: 68.75em`. "Touch" means `(hover: none)`; "pointer" means `(hover: hover)`.

## 1. Thesis and system

### 1.1 Thesis

1. A Housecall server is someone's house, so the interface is a house at night. You stand in the hall (the shell) and look into rooms (the stage).
2. One idea carries every state: **light means someone is home.** The accent is the lit doorway. A room with people in it has its light on, an empty one is dark, and nothing else gets the accent.
3. One shape signs the product: the doorway arch, round top and flat base. Avatars, the number plates of QR login, the seal on a letter, the bow of the key, every empty state and the splash are that arch.
4. From Discord we take the model and none of the look: text and voice channels as two lists, seeing who is in a room before you enter, one click to walk in, nobody rung, a LIVE mark with a peek at the stream, a call card that follows you, your name at the bottom left.
5. Better than Discord: calm. No server rail, no promotions, no badges competing. One accent, two weights, sentence case, a number only where the number is the news.
6. Better: touch is first class. Nothing is revealed by hover alone, a phone gets a sheet where a desktop gets a popover, and actions arrive at the thumb.
7. Better: honest. Latency is the measured number or nothing. "End-to-end encrypted" appears only where it is true, and a call says "relayed by the host".
8. Better: depth from tone, not lines. Two surfaces, washes of ink for hover and selection, one tight shadow for things that float. No borders on boxes.
9. Better: motion that means something. A door opens when you arrive, rows glide when someone goes live, the edge of a tile lights when its person speaks. Transform and opacity only; with reduced motion nothing moves and nothing is missing.
10. The test for any new piece: could it sit unchanged in another chat app? If yes, it is not finished.

| `--hc-stagger` | `60ms` | Delay between siblings that enter in turn |

Rules that follow from them:

| Area | Rule |
|---|---|
| Type scale | 11 / 12 / 14 / 16 / 19 / 26 / 36 px. `2xs` marks, `xs` meta (time, group labels, status lines), `sm` secondary rows and buttons, `md` body and channel names, `lg` the one title in a header bar or sheet, `xl` a page title, `2xl` one headline on a full-screen page. Two weights only, regular and bold. Never letterspaced capitals except the word LIVE. Numbers are tabular everywhere |
| Spacing rhythm | Rows in a list: 2 px apart. Groups: `--hc-space-4`. Inline icon to text: `--hc-space-2`. Card padding: `--hc-space-4`. Pane padding: `--hc-space-5`, phones `--hc-space-3`. Text never touches an edge: 8 px minimum inside any filled shape |
| Elevation | 0: flat, tone only. 1: a card in the flow, `--hc-surface-raised` plus `--hc-lip`. 2: floating, `--hc-pop` plus `--hc-float`. There is no other shadow |
| Radius | `xs` marks, `sm` rows and small buttons, `md` buttons, fields, cards, `lg` panels, sheets, tiles. A shape nested in a padded parent uses the parent radius minus the padding, or the next step down |
| Focus ring | `2px solid var(--hc-focus)`, `outline-offset: 2px`, always in the control's own radius. Inside a clipped tile the offset is `-2px` |
| Density | Pointer: rows 32 px, icon buttons 32 px, 30 px in toolbars, 24 px inside rows. Touch: rows 48 px, every target 44 px or more |
| Borders versus tone | A drawn line (`--hc-line`, 3:1) is only the boundary of a form field you type a value into. Everything else separates by tone step. Hover and selection are washes, so they read on the shell, the stage and a card alike |
| Accent | Solid and small: primary button, count, LIVE, lit glyph, speaking edge, send. Never mixed into a surface, never a wash, never a bar on an edge |
| Hover | Every `:hover` that tints or reveals is inside `@media (hover: hover)`. A control that appears on hover also appears on `:focus-within`, and has another route on touch |
| Text on pictures | A caption over video sits on a chip of `color-mix(in oklab, var(--hc-stage) 80%, transparent)`. No blur |

Shared pieces defined here and used by later sections: `.hc-tip` (a real tooltip), `.hc-face` (avatar with a speaking ring), `.hc-avatar--xs` and `--xl`, `.hc-sheet` (a bottom sheet on phones, a centred dialog on wide screens), `.hc-popover`, `.hc-note`, `.hc-empty` with the doorway drawing, `.hc-skel`.

`.hc-sheet` behaviour: `role="dialog"`, `aria-modal="true"`, focus moves to its first control, Escape and a tap on `.hc-sheet-scrim` close it, focus returns to what opened it. Phone: enters with `hc-anim-rise` (existing), leaves 110 ms. Wide: enters with `hc-anim-pop`. Wrap both scrim and sheet in the existing `Presence`.

`.hc-tip` behaviour: the trigger has class `hc-tipped` and `aria-describedby` pointing at the tip; the tip is `role="tooltip"`. It shows on hover after 350 ms, on keyboard focus at once, and on touch when the trigger is tapped (toggle `data-open`; any other tap removes it). `data-side="start"` or `"end"` pins it to that edge of the trigger when the centre would leave the column.

`useFlip` (new, `client/src/ui/tokens/motion.ts`). No library: it measures before and after and plays a transform with the Web Animations API.

```ts
/** Children of `ref` that keep their `data-flip` key glide to their new place when the list changes. Transform only. */
export function useFlip(ref: RefObject<HTMLElement | null>, order: string) {
  const before = useRef(new Map<string, number>());
  useLayoutEffect(() => {
    const parent = ref.current;
    if (!parent) return;
    const rows = [...parent.querySelectorAll<HTMLElement>("[data-flip]")];
    const reduced = prefersReducedMotion();
    for (const row of rows) {
      const key = row.dataset.flip!;
      const top = row.offsetTop;
      const was = before.current.get(key);
      if (!reduced && was !== undefined && was !== top) {
        row.animate([{ transform: `translateY(${was - top}px)` }, { transform: "none" }], { duration: 190, easing: "cubic-bezier(0.2, 0.8, 0.2, 1)" });
      }
    }
    before.current = new Map(rows.map(row => [row.dataset.flip!, row.offsetTop]));
  }, [order]);
}
```

Use: `useFlip(listRef, people.map(p => p.id).join())` on the `ul.hc-group__list` of voice channels, with `data-flip={channel.id}` on each channel `li` and `data-flip={person.id}` on each `.hc-vrow`. A leaving row keeps its place for 110 ms (`Presence` with `ms={110}`), then the rows below glide up.

## 4. LIVE mark and stream preview

Mockup: `live-preview.html` (states `default`, `loading`, `none`).

### 4.1 The LIVE mark

A small solid plate: `--hc-live` fill, `--hc-on-accent` text, the word LIVE in `--hc-text-2xs` bold with `0.06em` tracking, 18 px tall, `--hc-radius-xs`. No dot, no glow, no ring. It is a `button` (it opens the preview); its hit area is extended by 8 px above and below and 6 px to each side. In a caption on the stage it is a `span` (not interactive). In the phone sheet it is 28 px tall.

Shown on a person exactly while their voice state has `sharing: true`.

Motion: when it appears it lands with a small spring (opacity and scale from 0.6, `--hc-dur-slow`, `--hc-ease-spring`), breathes three times (opacity to 0.55 and back, 1.6 s each) and then rests. Nothing in the sidebar blinks forever. Add the class `is-entering` for the first 5.2 s after `sharing` turns true, then remove it. Reduced motion: it simply appears.

## 6. Call card

Mockup: `call-card.html` (one board with every state), and in place in `sidebar.html` and `voice-stage.html`.

The call card replaces `CallDock`. It sits in the left column directly above the user bar for as long as you are in a call or joining one, on every screen including the stage (the sidebar must not change when you move between rooms).

### 6.1 Anatomy

```html

```

One row, 52 px tall, `--hc-surface-raised` with `--hc-lip`, `--hc-radius-md`. The signal is 28 x 28; the middle is the channel name (bold, `--hc-text-md`) over the status (`--hc-text-xs`); the three controls are 32 px icon buttons, 2 px apart. The name truncates; the controls never move. Leave is `--hc-danger` at rest. Camera and screen share live only on the stage bar.

### 6.2 Signal bars

Three bars, 3 px wide, 5 / 9 / 13 px tall, 2 px apart, 1 px radius, bottom aligned. Unlit bars are the same colour at 28% opacity.

| `data-bars` | When (`call.quality`, from `getStats()`) | Colour |
|---|---|---|
| `3` | RTT under 80 ms and loss under 2% | `--hc-live` |
| `2` | RTT under 200 ms and loss under 6% | `--hc-live` |
| `1` | anything worse while connected | `--hc-danger` |
| `0` | failed, or no measurement yet | `--hc-text-muted` |
| `data-busy` (with `0`) | connecting or reconnecting | The bars light in turn, 1.05 s loop, 150 ms apart, opacity only. Reduced motion: the first bar is lit, still |

The number of lit bars carries the level; colour only agrees with it.

Tooltip (`.hc-tip`, by hover, keyboard focus, or tap): "32 ms to server" with the measured round-trip time. Before the first measurement: "Measuring". Failed: "No connection". Never an invented number (UI contract).

### 6.3 States

| `data-state` | Bars | Line two | Line-two colour | Controls |
|---|---|---|---|---|
| `connecting` | 0, busy | Connecting | `--hc-text-muted` | Mute and deafen disabled, Leave enabled |
| `connected` | 2 or 3 | Voice connected | `--hc-live` | all |
| `weak` | 1 | Weak connection | `--hc-danger` | all |
| `reconnecting` | 0, busy | Reconnecting | `--hc-text-muted` | all (your mute choice is kept) |
| `failed` | 0 | Call failed | `--hc-danger` | "Try again" (a small `.hc-btn`) and Leave |

In a DM call line one is the other person's name and line two reads the same. Muted and deafened buttons are pressed (`is-active`, crossed icon).

Clicking the name opens the stage (closing the drawer on a phone). The `aria-label` of that button is "Open Lounge".

### 6.4 Phone

In the drawer the card is the same, with 44 px controls (the existing phone rule for `.hc-ibtn`).

Outside the drawer, on every centre screen that is not the stage (a text channel, a DM, settings), a **call strip** sits directly under the header: 48 px tall, 8 px side margins, raised with the lip. Signal (44 px target), then name and status on one line, then Mute and Leave (44 px each). Deafen is in the drawer card and on the stage. Tapping the name opens the stage. On the stage the strip is hidden and the header carries the signal.


### 6.5 Motion

The card rises 8 px with opacity when a call starts (`--hc-dur-slow`, `--hc-ease-out`) and drops 4 px and fades when it ends (`--hc-dur-fast`, `--hc-ease-in`); wrap it in `Presence` with `ms={110}`. The channel list above it shortens by the card's height at once; that is acceptable because the list scrolls and the card appears at its foot. Status text changes without motion.

## 8. Message actions

Mockup: `message-actions.html` (states `default`, `closed`).

The mechanism is plan A1: `MessageList` owns one open id; a message is `.is-open` only while it is that id; a `pointerdown` anywhere outside it, or Escape, clears it.

### 8.1 The bar

```html
<div class="hc-msg__bar" role="toolbar" aria-label="Messages">
  <button type="button" class="hc-ibtn" aria-label="Reply"><Icon name="reply"/><span class="hc-msg__lab">Reply</span></button>
  … React, Pin (or Unpin), Preview, Edit, Unsend (hc-ibtn--danger) …
</div>
```

`IconButton` gains an optional `text` prop that renders `<span class="hc-msg__lab">` after the icon; the message bar passes each button's label. The span is hidden on wide screens and visible in the phone tray, and it is `aria-hidden` (the button already has its `aria-label`). Order: Reply, React, Pin, Preview (only when the message has a link and no preview yet), Edit (yours), Unsend (yours or owner). "Preview link" is shortened to "Preview" for the tray label; the `aria-label` stays "Preview link".

### 8.2 Wide screens

- The bar rides the top edge of the row at the right: `top: -18px` (grouped rows `-22px`), `right: 0` of the message column. Fill `--hc-pop`, `--hc-float`, `--hc-radius-md`, padding 2 px; buttons 30 x 30 with 18 px icons, `--hc-radius-sm`.
- Shown when: the pointer is over the row (`@media (hover: hover)` only); the row or anything in it has keyboard focus; or the row is `.is-open` (a click on the row's text toggles it).
- The row shows `--hc-wash-hover` behind it in the same cases.
- Keyboard (unchanged): the list is one tab stop, arrows move between rows, Enter moves into the bar, Escape returns to the row.
- Each button shows a `.hc-tip` with its label (replaces `title`).
- Motion: opacity and 2 px rise in `--hc-dur-fast`, out `--hc-dur-fast`.

### 8.3 Touch (phones)

- Tap a message: it becomes `.is-open` (wash `--hc-wash-selected`) and the same toolbar appears as a **tray** fixed to the bottom of the screen, over the composer: full width, `--hc-pop` with the lip, top corners `--hc-radius-lg`, padding 8 px plus the bottom safe area. Six equal buttons, 56 px tall, icon 22 px over an 11 px label. Unsend is `--hc-danger`.
- Nothing in the list moves when it opens or closes.
- Tap another message: the tray stays and now acts on that message (the open id changes; no close and reopen motion). Tap anywhere else (the header, empty space, the composer): it closes. Scrolling the list does not close it.
- One open at a time, by construction.
- "React" opens the emoji picker under the message as today and closes the tray; "Unsend" opens the inline confirm under the message as today.
- Motion: the tray slides up from below the screen edge, `translateY(100%)` to 0, `--hc-dur-base`, `--hc-ease-out`; down in `--hc-dur-fast`, `--hc-ease-in`. It is hidden with `visibility` so it never takes a tap while closed. Reduced motion: appears and disappears in place.
- A touch screen wider than a phone gets the wide bar on tap (`.is-open`), with 44 px buttons (`(pointer: coarse) and (min-width: 47.51em)`).

The tray is `position: fixed`. Its nearest ancestors must not create a containing block: do not put `transform`, `filter`, `contain` or `will-change` on `.hc-messages` or `.hc-msg`. `.hc-center` is full screen on phones, so its slide transform is harmless.

No new keys except `messages.previewShort`: "Preview".

## 9. Snap camera

### 9.3 States and behaviour

| State | What shows |
|---|---|
| Starting | The layer in `--hc-night`, the controls present, the shutter disabled until the first frame |
| Live | As drawn. The rear camera is the default on phones, the only camera on most desktops (the flip button is absent when there is one camera) |
| Flash, rear camera | The button toggles the torch constraint when the track supports it. On: `.is-lit` (the accent), no slash. If the track has no torch the button is absent |
| Flash, front camera | On capture `.hc-cam__fill` turns the whole screen white for 240 ms around the capture, then clears |
| Capture | `.hc-cam__blink` flashes once (190 ms); the frame is drawn to a canvas at the track's native resolution; the layer becomes `.is-review` with the still |
| Review | The still, full bleed. Close top left (discards). "Each person can open it once" above the actions. "Retake" at the left returns to live. "Send" at the right sends and closes the layer. While sending: the button is busy with the label "Sending" |
| Gallery | Opens the system file picker (the old input without `capture`); the chosen picture goes to review |
| Blocked | `getUserMedia` refused, or no camera: `.hc-cam__blocked` with the crossed camera icon, "Housecall can't use the camera", one line, "Try again" and "Choose a photo instead". In QR mode the second button is absent |
| Keyboard | Space or Enter on the shutter captures; Escape closes (review: Escape is Retake); focus is trapped in the layer and returns to the snap button on close |

### 9.4 QR scan mode

The same component with `mode="scan"` (`hc-cam hc-cam--scan`): no shutter, gallery or flip.

- Frames are sampled to a canvas and decoded with `jsqr` at most 8 times a second, on the centre square only.

| 410 ms | The doorway lights | `hc-fade-in`, `--hc-dur-base`, delay `--hc-dur-fast` |
| 490 ms | The door swings open from its hinge; light falls on the floor | `hc-splash-door` (`scaleX` 2.35 to 1), `--hc-dur-slow`, `--hc-ease-spring`, delay `--hc-dur-base`; the spill fades in with it |
| 620 ms | The rise has ended (`animationend` on `.hc-splash__rise`). From here the splash leaves as soon as the app is ready | |
| 620 ms, ready | Set `data-out="fly"` and the shell's `data-enter`. The mark travels to the picker's logo; the floor light goes out; the sidebar rises, then the room | `hc-splash-fly`, `--hc-dur-slower`, `--hc-ease-out`; `hc-shell-in` (12 px, fade), `--hc-dur-slow`, the room `--hc-stagger` later |
| 1180 ms | `animationend` on the mark: remove the splash, remove `data-enter` (which shows the real logo in the same frame) | |
| Still not ready at 1.4 s | The door breathes | `hc-splash-wait`, 1.4 s, alternate, until ready |
| Still not ready at 4 s | The status line fades in | `hc-fade-in`, `--hc-dur-slow` |

The door may still be settling while the mark flies. That is intended; nothing waits for it.

### 13.3 Landing

Just before the exit, in a layout effect and before `data-enter` is set (so no entrance transform is in the measurement), read where the mark is and where it is going:

```ts
const a = splash.querySelector(".hc-splash__mark")!.getBoundingClientRect();
const b = document.querySelector(".hc-picker .hc-logo")?.getBoundingClientRect();
if (b && b.width > 0 && b.right > 0 && b.left < innerWidth) {
  splash.style.setProperty("--hc-splash-dx", `${b.left + b.width / 2 - (a.left + a.width / 2)}px`);
  splash.style.setProperty("--hc-splash-dy", `${b.top + b.height / 2 - (a.top + a.height / 2)}px`);
  splash.style.setProperty("--hc-splash-s", String(b.width / a.width));
  splash.dataset.out = "fly";
} else {
  splash.dataset.out = "fade";
}
shell?.setAttribute("data-enter", "");
```

- `fly`: wide screens, and phones that open on the channel list. While `data-enter` is set the picker's own logo is hidden, so there is one mark on screen at every moment.
- `fade`: there is no picker logo on screen (a phone that opens in a conversation, Welcome, sign-in, the recovery screens). The mark shrinks to 0.92 and fades in `--hc-dur-base`, `--hc-ease-in`; what follows enters with its own motion.
- Phone: the shell rises as one piece (the parked column would otherwise show through the other).

### 13.4 When it is skipped

| Case | What the user sees |
|---|---|
| Ready within 300 ms of mount | No mark at all. The shell enters with `hc-shell-in` (set `data-enter`, remove it on `animationend` of `.hc-center`) |
| Reduced motion | No grace-period difference: the mark appears whole at 300 ms if still waiting, and the whole splash fades in `--hc-dur-base` when ready. No flight, no shell entrance, no breathing; the status line still appears at 4 s (set by a timer, not by animation) |
| Coming back from the background, a reload of a live web tab that is ready within 300 ms, switching servers, signing out and in | Never shown again in the same process. It plays at most once per launch |
| The `/link` page | Never |

### 13.5 Copy

| Key | String |
|---|---|
| `splash.label` | Opening Housecall |
| `splash.status` | Opening {server} |
| `splash.statusNoServer` | Opening Housecall |
| `splash.slow` | Still trying to reach {server} |

`splash.slow` replaces the status line after 12 s; the existing offline handling takes over from there.
