# SFU reliability review — 2026-11-07

Observed load evidence remains `client-voice-load.json`: all five peers received four audio/video streams; at ten peers, two had zero audio and video and several others had incomplete fanout. The fixture allowed seven seconds for each stage to settle. This evidence does not establish a root cause.

The installed str0m 0.25.0 source (`src/channel.rs`, `Channel::write`) checks aggregate available SCTP buffer space and returns `Ok(false)` before writing any bytes when insufficient. The old SFU disconnected immediately on that temporary condition. It now retains exactly one signaling payload per peer, bounded to 128 KiB, retries no more often than every 10 ms, and disconnects with a fixed reason after five seconds without acceptance. A pending offer also has a 15-second answer deadline. Protocol errors still disconnect. No inbound SDP/message limit was raised.

The deterministic send regression injects temporary backpressure into the production queue helper, verifies pacing, byte preservation and exactly one accepted send, then checks deadline, oversized-message and fatal-write paths. It does not claim to reproduce real SCTP congestion in the ten-browser scenario. The existing real localhost UDP test separately verifies three-peer encoded-media forwarding, room isolation and revocation. The parser proptest remains enabled.

Optional stats contain per-peer ICE state, packet counts, forwarding-not-ready/codec counters, track states, pending-offer age, signaling queue size/backpressure, and message byte/m-line counts. A separate history retains at most 120 disconnected peers globally for 60 seconds and returns at most 30 records from the authorized room; it is excluded from active-peer/admission counts. History tests verify bounds, expiry, room filtering and no saved session secret. Worker diagnostics record maximum loop duration and batch counts. Fixed disconnect logs contain opaque peer IDs and reason codes, not SDP or credentials.

The load fixture records bounded signaling metadata, terminal browser ICE/connection/signaling states, per-stream RTP counts, transceiver directions, safe error categories, and an authenticated SFU snapshot. It never saves SDP, candidate addresses, bearer/device credentials or media. With zero active peers, the stats endpoint remains unavailable by design; fixed-code server logs and browser diagnostics are then the evidence sources. The active-session authorization boundary was not widened.
