# DJ playback slice — 2026-11-07

The existing revisioned DJ activity supplies the authoritative queue, host play/pause/seek, member votes, skips and anchored playback clock. New authenticated routes resolve one best match, prepare local playable audio, enqueue only server-generated metadata and serve the current track. The clock worker advances finished tracks and persists/broadcasts changes. Generic unprepared enqueue is rejected when the production player is configured.

Each prepared asset contains a local spoken introduction followed by the song, encoded by FFmpeg as stereo 510 kbps-target Ogg Opus. Consequently the introduction participates in the same clock and skip behavior as the song. Banter introduces the next title without asserting which prior song played, since intervening removals/skips can change it. Switchboard receives `role:chat` and `X-Inference-Task: chriscord.dj`; speech uses local espeak-ng by default, or the existing offline CPU clone command adapter with operator-provided reference/model files. No hosted clone is used.

Resolver input accepts only supported YouTube/SoundCloud/Spotify links or a plain search query. Spotify uses an operator-supplied access token to obtain metadata, then resolves a YouTube search. yt-dlp is time/output bounded, ignores configuration/plugins, selects direct HTTPS audio, explicitly enables the configured local Node/Deno runtime and prohibits remote EJS component downloads. Relevant primary sources: [EJS setup](https://github.com/yt-dlp/yt-dlp/wiki/EJS) and [pinned 2026.08.19 CLI options](https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/yt_dlp/options.py).

Resolved CDN addresses stay server-private. Download accepts GoogleVideo/SoundCloud CDN suffixes over HTTPS, rejects credentials/fragments/non-443 ports, resolves and rejects special/private addresses, pins the validated DNS address, disables proxies and never follows redirects. Decoders permit only local file/pipe inputs and audio-container demuxers, excluding network playlists. Scratch media lives only on a checked tmpfs directory; finished and partial cache payloads use the existing authenticated encrypted media store. Production scanner approval is mandatory; test scanner accepts only fixture Ogg payloads and is not malware-scan evidence.

Bounds: one preparation at a time, source≤32 MiB, song≤15 minutes, intro≤60 seconds, output≤64 MiB, cache payload quota≤512 MiB/128 assets with a full output reservation during preparation, and 32 bounded streams with two 64 KiB chunks buffered per stream. These are DJ cache limits; general uploads remain independent. A cancelled preparation is unavailable and cleaned after ten minutes or restart. Unqueued ready assets expire after one minute; activity stop invalidates pending preparations and purges its cache. The audio route rechecks session, channel, active voice membership and current track between reads on a one-second interval while streaming.

Routes:

- `POST /api/channels/{id}/dj/search {query}` → `{results:[{title,source,duration_ms}]}`. No playable CDN URL or provider token is serialized.
- `POST /api/channels/{id}/dj/queue {query}` → `{track_id,intro_ms,activity}` after successful preparation/scan.
- `GET /api/channels/{id}/dj/playback` → `{track:null|{id,intro_ms,duration_ms,audio_url},activity}`.
- `GET /api/channels/{id}/dj/audio/{track}` → authenticated `audio/ogg`, byte ranges, current track only.

Runtime configuration is opt-in (`DJ_ENABLED=true`) and requires media encryption/scanning and the SFU. Tools: `YT_DLP_BIN`, `FFMPEG_BIN`, `FFPROBE_BIN`, `ESPEAK_NG_BIN`; `DJ_JS_RUNTIME` defaults to `node`; `DJ_TMPFS_DIR` defaults to `/dev/shm/chriscord-dj`. Optional provider settings: `SPOTIFY_ACCESS_TOKEN`, `SWITCHBOARD_API_KEY`. Clone selection: `DJ_TTS_COMMAND`, `DJ_REFERENCE_WAV`, `DJ_TTS_MODEL_DIR`. Operator must provision a tmpfs and avoid unencrypted swap for plaintext staging memory. No reference clip or real clone quality is claimed.

Verified receipts: adapter tests in `activities-dj-adapter-tests.log`; authenticated route/local audio tests in `activities-dj-server-tests.log`. Metadata, CDN, Switchboard and scanner are fixtures; espeak-ng, FFmpeg, encrypted storage and three local UDP voice connections are real. All executed provider operations use literal loopback fixtures. No real YouTube/SoundCloud/Spotify/Switchboard calls were performed; progressive-only extraction means some sources may be unsupported, and live provider compatibility remains unverified. Spotify access-token refresh is operator-managed. Browser playback uses a bounded full-track blob, not progressive start.

The isolated browser fixture passed in 9.96 seconds (`activities-dj-browser-tests.log`, `activities-dj-three-browser.json`). Three Chromium instances using the real `DjPlayer` decoded the authenticated Ogg streams, paused and sought to exactly 7.000 seconds, resumed with a sampled 25.114 ms position spread, and played the next track after two votes. Initial and post-skip sampled spreads were 61.488 ms and 25.481 ms. These are player-position samples on one host, not acoustic latency measurements. Voice authorization came from three separate actual UDP fixture peers; browser voice RTP is not claimed by this DJ test. No browser/player errors were recorded. Rust formatting check passed using the project edition 2021.
